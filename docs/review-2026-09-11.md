# Review 2026-09-11 — after phase opus-1, before opus-2

Fable review at the lane boundary (build method: `phased-autonomous-build`). One read of
the merged foundation (PR #2) and of the plan/prompts, then decisions written into files.
Everything below is **decided**, not proposed. Build sessions execute it; they do not
re-open it.

## 1. What is good and stays

- The schema is complete and careful: integer guaraníes everywhere, foreign keys with
  sensible cascades, unique idempotency key on the ledger, price snapshot on the
  assignment, unguessable tokens with only hashes stored for spoke tokens. Frozen as-is.
- Ledger service (`src/lib/credits/ledger.ts`) locks the professional row `FOR UPDATE`,
  checks idempotency inside the transaction, updates the cache in the same transaction.
  Correct design. It was proven against a real MariaDB with 4 concurrent charges.
- Auth is a small HMAC cookie verified in constant time, guards exist at both the
  middleware and server-component layer, `next` redirect is open-redirect-safe.
- Idempotent seed, typed i18n with compile-time key checks, lazy DB pool so CI builds
  without a database, `/api/health` splits app from DB status. All keep.

## 2. Findings in the foundation code (→ fixed by the phases named)

| # | Finding | Severity | Fix in |
|---|---|---|---|
| F1 | **Suspending a user does not end their session.** Session is a stateless 30-day cookie; `requireRolePage`/`requireRole` never re-check `users.status`. A suspended pro keeps `/panel` and every API for up to 30 days. | High (admin "suspend" is a launch feature) | opus-2: `getSession()` loads `users.status` (one indexed PK read, cached per request) and treats `suspended` as no session. Test it. |
| F2 | **Production can boot with the default admin password.** `ADMIN_PASSWORD` falls back to `cambiar-esta-clave` in both `env.ts` and `seed.ts`; `assertProductionEnv` does not check it. | High | opus-2: seed refuses to create/update the admin in production without `ADMIN_PASSWORD`; `assertProductionEnv` reports it. |
| F3 | **No rate limiting on login** (already in KNOWN-ISSUES). | Medium | opus-2 builds one limiter for lead intake and applies it to `/api/auth/login` in the same phase. |
| F4 | **Tests never touch MySQL.** Ledger concurrency was verified by hand against MariaDB 10.11 and cannot be re-run; production is MySQL 8. The most money-critical code of the build has no repeatable DB test. | High | opus-2: add a MySQL 8 **service container to the existing CI job** (still one workflow, one job — §1.11 shape unchanged) and a `tests/integration/` suite that runs when `DATABASE_URL` is set, skips otherwise. Ledger, matching, accept-idempotency and expiry are tested there against real transactions. |
| F5 | **`recomputeBalance` is not transactional** — a charge landing between its SUM and its UPDATE writes a stale cache. | Low (admin-only repair tool) | opus-2: lock the professional row for the recompute. |
| F6 | **`/api/health` leaks the DB error string** (`detail`) publicly. Connection strings can appear in mysql2 messages. | Low | opus-2: return `detail` only when `NODE_ENV !== "production"`. |
| F7 | **Brand-agnostic rule (§1.13) leaks:** `env.ts` and `seed.ts` default to `admin@profesionales.com.py`, SMTP_FROM to the same domain. | Low | opus-2: derive defaults from `NEXT_PUBLIC_SITE_URL` host; no domain literals in `src/`. |
| F8 | **Middleware blocks admins from `/panel`.** Admins will want to see what a pro sees. | Low | opus-3: allow admin read-only on `/panel` via an "impersonation-lite" query (`?as=<proId>`) guarded server-side; not before. |

Nothing above changes the schema. Nothing is a stop-and-ask.

## 4. Model per phase (decided)

Opus for anything later phases build on or that touches money/auth/matching:
opus-2 (lead engine), opus-3 (pro + admin + reviews). Sonnet for everything that fills an
existing shape: the four parallel lane-2 phases and the final link/QA pass. All Opus work
runs first, sequentially; all Sonnet work starts when opus-3 merges. Fable never runs a
phase (§4.8). The watcher runs on Sonnet.

| Order | Phase | Model | Runs |
|---|---|---|---|
| 1 | opus-2 lead engine | Opus | now |
| 2 | opus-3 pro dashboard, admin, reviews | Opus | after 1 merges |
| 3 | sonnet-1 design system + public pages | Sonnet | parallel, after 2 merges |
| 3 | sonnet-2 content: category copy, price guides, legal | Sonnet | parallel |
| 3 | sonnet-3 technical SEO + imagery + OG | Sonnet | parallel |
| 3 | sonnet-4 deploy docs + production seed + CRM verify | Sonnet | parallel |
| 4 | sonnet-5 link pass + production QA + closing report | Sonnet | after all of 3 merge |

Expected cost: opus-2 ~$30, opus-3 ~$25, lane 2 ~$10 each in parallel, link pass ~$8,
watcher cents per firing → roughly $100–110 for the remainder, ~5 h wall-clock if the
watcher never has to restart anything.
